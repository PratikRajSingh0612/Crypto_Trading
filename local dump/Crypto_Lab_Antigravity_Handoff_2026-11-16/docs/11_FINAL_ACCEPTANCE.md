# 11. Product definition of done and evidence matrix

## Core completion is not full-programme completion

Project 1 acceptance follows the current architecture section 33 and Stage 10's exact criterion matrix. The inspected plan names 62 acceptance cells. Close every mandatory cell using actual evidence and disposition actual B1/B2/B3 dependencies. A task can be accepted while a programme criterion remains blocked; report both.

## Release-level checks

| Release | Required demonstrable result | Not sufficient |
|---|---|---|
| Core R0 | CLI/composition, fake-adapter success and adverse paths, restart, persistence, artifacts, audit, security and build/installation evidence | Source scaffolding or green unit tests alone |
| One-engine R1 | Production-compliant dataset registered; supported strategy; actual engine; finalized real outputs; reproducible inspection/reopen | Synthetic fake engine or interim file called Parquet |
| Seven-engine R2 | Every required adapter executes its declared supported scope and comparison behavior is explicitly qualified | Seven descriptors or seven unavailable statuses |
| User workflows R3 | Restart-safe hypothetical wallet/risk, sourced versioned tax estimates, local UI backed by real services | Mock dashboard or unsourced tax constants |
| Local assistant R4 | Optional genuinely local model explains immutable evidence with resolvable references; no write authority; deterministic use works with it absent | Cloud fallback labelled local or generated numbers treated as truth |

## Adverse workflows to preserve

Invalid configuration/strategy, unknown input fields, missing dataset, unsupported capabilities, unavailable engine, rejected negotiation, malformed or out-of-sequence events, deadlines, cancellation, child exit/crash, stale output, database conflict/unavailability, partial file move, restart at each finalization phase, token leakage, invalid owner/purpose, duplicate replay, and deliberately incomplete quality intervals.

Each acceptance entry must state what actually ran, the exact commit/tree, fixture/real-data identity, environment, expected observable result and proof. Use `state/acceptance_template.json`; do not fill unknowns with guesses.

## Numeric and user-facing truth

Explicitly disclose signal and fill timing, precision conversion, sizing, costs, slippage, unsupported features and nondeterminism. No guarantee of profitability. No false successful state, complete dataset, authorized audit or actual real-data test based solely on generated artifacts.

## Documentation/release package

Versioned capability/feature matrix; operator setup and normal/adverse examples; dependency and licence record; exact source/data provenance; accepted installation and schema distribution; safe demo fixtures; known limitations; reproducible local run; clean expected Git state; observed publication identity. Raw data, credentials, model weights and private execution evidence are not automatically public source deliverables.
