# 12. Effective development authority for Antigravity

## Owner direction embodied by this handoff

The owner requests full takeover by Google Antigravity, no future Claude Code or OpenAI/Codex development, local-first autonomous delivery and removal of unnecessary process restrictions. This package is an operational translation to adopt in the local workspace; producing the ZIP did not execute or approve unseen changes on the user's machine.

## Routine engineering should proceed

Read relevant local code/evidence, choose the next in-scope task, prepare just-in-time plans, correct implementation defects, create tests/docs, run the intended project tools, group coherent corrections, review, checkpoint, commit and publish accepted work to the existing authorized repository. Do not ask the owner to route an ordinary technical decision through another model.

The former controller's turn/spend/retry counts, launch-classifier hooks, mandatory pilot-before-every-restart, exact provider prompts and human-launch-only wrappers are historical. They do not have to be recreated. Preserve their original records but do not allow their retired mechanics to block an equivalent direct Antigravity workflow.

Within adopted local-development authority, select reasonable local project tools/dependencies and document exact versions, sources and licence/compatibility implications. Use supported permission routes. Preserve explicit exceptions already granted (such as isolated VectorBT 1.2.0) and avoid gratuitous reacquisition. No package may be silently installed into the wrong project environment.

## Things 'local' does not establish

Locality does not imply permission to read secrets, disable security, cross OS/enterprise restrictions, purchase software, expose services, overwrite unrelated files, trade real funds, ignore licences, fake tests or change material product behavior without an explicit recorded design decision.

Google-hosted inference is not local-only inference. Source sent to a hosted model follows the user's Antigravity/account policy; this package does not promise that code remains entirely on the machine. Product P13's eventual local LLM remains a different deliverable.

## Changes to product requirements

Distinguish process simplification from changing observable behavior. A coherent, compatible design decision within approved scope can be recorded by delegation. Material departures such as live trading, a new financial instrument class, removing a mandatory engine, destructive migrations, additional external accounts/payment or incompatible licence terms still need an explicit product decision.

Do not misclassify closed audit facts, normalized schemas or finalization safety as mere wording. Use their owning-stage correction and compatibility evidence. The owner has requested less overhead, not false completion.

## Stop and checkpoint

Respect explicit owner STOP/PAUSE instructions and real platform permission denials. No hidden relaunch, auto-clearing unrelated stops or command obfuscation. At a quota/session limit, persist progress and resume through supported Antigravity mechanisms. No guarantee of perpetual background execution is made.

## Publication authority

The standing mandate allows accepted commits/branches and gated main integration to the existing authorized GitHub repository. No new remotes, visibility changes, force publication or history rewriting is implied. Resolve divergence honestly. Retain private evidence locally and run the outgoing-range check before publication.
